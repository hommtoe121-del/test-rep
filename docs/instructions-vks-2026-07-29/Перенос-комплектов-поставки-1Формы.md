# Перенос комплектов поставки 1Формы

Инструкция по **экспорту / импорту конфигурации** (комплекты поставки настроек) между контурами 1Формы: Dev → Test → Prod, по разбору на ВКС.

**Источник:** запись ВКС от 29.07.2026  
https://vks.oro.moscow/records/3f9b19c6-daa7-46c3-a583-b04e468fe89b/9f10fczreo5gnbdf_2026-07-29-16-47-43.mp4

**Системы:**
- Пример Dev admin: https://192.168.216.118/spa/administration
- Экспорт конфигурации: https://192.168.216.118/spa/administration/config-export
- Импорт конфигурации: https://192.168.216.118/spa/administration/migration/import

---

## 1. Зачем это, а не полный бэкап

На записи отдельно от restore бэкапа разобран сценарий **точечного переноса** изменений:

- добавили/изменили доп. параметр (ДП);
- поменяли маршруты / разрешения;
- добавили смарт-правила, смарт-расписания, пакеты действий.

**Устно:** «сразу всё тащить не надо» — 1Форма **плохо** переносит категории целиком. Надёжнее переносить **изменённые сущности**, а не весь контур.

Полное выравнивание через бэкап — другая инструкция:  
https://github.com/hommtoe121-del/test-rep/wiki/Разворачивание-бэкапа-1Формы

## 2. Общая схема

| Этап | Где | Действие |
|---|---|---|
| 1 | Исходный контур | Администрирование → **Экспорт конфигурации** |
| 2 | Исходный контур | Отметить нужные сущности → скачать zip-комплект |
| 3 | Целевой контур | Администрирование → **Импорт конфигурации** |
| 4 | Целевой контур | Выбрать файл → **Проверить** → разобрать цвета статусов → импорт |

Рекомендованный поток на записи: **Dev → Test**, затем **Test → Prod** (не прыгать «всем сразу» через все контуры без проверки).

## 3. Экспорт комплекта

Откройте на исходном сервере:

https://192.168.216.118/spa/administration/config-export  
(на других контурах — тот же путь `/spa/administration/config-export` у их host)

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/perenos-komplektov-postavki/18-config-export.jpg)

На экране:
- раздел **Экспорт конфигурации**;
- статус полной выгрузки справочников (на записи: `Finished`);
- дерево сущностей по категориям (в т.ч. **Бизнес-циклы (65)**).

Пример ветки БЦ / доп. параметров:

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/perenos-komplektov-postavki/19-config-export-bc.jpg)

Пример смарт-действий / `EventsActionEntity` (на записи: новые правила появляются **внизу** списка с большими id):

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/perenos-komplektov-postavki/20-config-export-events.jpg)

### Что выбирать

| Меняли | Что экспортировать |
|---|---|
| Только новое/изменённое поле (ДП) | сам доп. параметр (внутри уже ролевка, статусы, локализации и т.д.) |
| Автоматизация | соответствующие смарт-правила / пакеты / `EventsActionEntity` |
| Маршруты / разрешения категории | соответствующие узлы категории |

**Устно:** пакеты действий часто проще найти и перенести точечно, чем тащить «всю категорию».

После выбора — скачайте файл миграции (на записи при импорте фигурировал zip вида `ORO CRM_2026-07-27T08-36-03.zip`).

## 4. Импорт комплекта на целевом контуре

Откройте:

https://192.168.216.118/spa/administration/migration/import  
(путь на целевом host: `/spa/administration/migration/import`)

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/perenos-komplektov-postavki/21-config-import.jpg)

Шаги:
1. **Выбрать файл миграции**
2. Нажать **Проверить** (не импортировать вслепую)
3. Опционально: «Показать только изменяемые»
4. Разобрать статусы строк
5. Импортировать

Пример после проверки:

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/perenos-komplektov-postavki/22-config-import-status.jpg)

### Как читать цвета / статусы (по записи)

| Вид | Смысл |
|---|---|
| Белый / «Без изменений» | на источнике и приёмнике одинаково — **не будет затрагиваться** |
| Зелёный / синий | изменения к переносу (добавление / обновление — смотрите колонку статуса) |
| Жёлтый | было обновление / внимание |
| «Добавить» | новой сущности на цели ещё нет |

На скрине: `EventsActions` → статус **Добавить**; ряд `SmartExpressionsVersions` / `Subcategories` → **Без изменений**.

**Устно:** если импорт ругается на повторяющиеся значения — часто признак, что контуры **не выровнены**. После выравнивания серверов таких конфликтов меньше.

Опция «Импортировать как новые сущности» — только если понимаете последствия (на записи: «если не знаете в чём проблема — бывает, но лучше разбирать»).

## 5. Практические замечания со встречи

1. Не переносить «всю категорию целиком» без нужды.
2. Если добавили только ДП — достаточно комплекта по этому ДП.
3. Новые смарт-правила ищите в конце списка (большие id).
4. Перед массовым переносом на Prod сначала прогоните тот же комплект на Test.
5. Если контуры сильно разъехались — сначала выравнивание через бэкап, потом уже точечные комплекты:
   - https://github.com/hommtoe121-del/test-rep/wiki/Выравнивание-серверов-1Формы

---

## 6. Чек-лист поддержки

- [ ] Понятен список реально изменённых сущностей (не «вся категория»)
- [ ] Экспорт на источнике собран и скачан zip
- [ ] На цели выполнен **Проверить**, разобраны статусы
- [ ] Нет неожиданных конфликтов дублей (иначе — выравнивание контуров)
- [ ] Импорт выполнен; точечно проверено поведение (правило / ДП / маршрут)
- [ ] Для Prod есть успешный прогон того же комплекта на Test
