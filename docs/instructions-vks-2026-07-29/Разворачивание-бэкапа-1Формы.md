## 1. Когда это нужно

На разборе названы три близких сценария:

| Сценарий | Что делаем |
|---|---|
| Откат боя | Восстановить БД боя из свежего бэкапа (это делает IT) |
| Выравнивание контуров | Развернуть копию боя на Dev/Test и **перенастроить** адреса |
| Поднять «положенный» контур | То же: restore БД + пост-настройка |

**Устно на записи:** если на бою полный коллапс — восстанавливают в основном **БД**; web-сервер отдельно. Настройки хранятся в БД.

## 3. Чек-лист разворачивания копии боя на целевой сервер

Опорная задача в 1Форме: **«Вопрос по развертыванию копии боя на новый сервер»** (#2070670).

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/razvorachivanie-bekapa/05-task-2070670-deploy.jpg)

### Шаг 1. Restore только БД

1. Согласовать с IT (на записи: Пётр / Юрий Холопов) restore свежего бэкапа боя на целевой DB-сервер.
2. Restore делают в PostgreSQL (pgAdmin → Restore) — **только БД**, не «весь сервер».
3. Документация, на которую ссылались в задаче:
   - https://help.1forma.ru/Maintenance/tech_req_1f_prepare_postgresql.htm
   - https://help.1forma.ru/Maintenance/docker_compose2.htm

**Устно:** при отличии major-версии Postgres (на записи: бой на 16-й, актуальная 18-я) restore делать **без расширений**, расширения поставить отдельно.

### Шаг 2. Подготовить SQL-скрипт под целевой контур

В задаче #2070670 лежит скрипт (на записи открывали `APT_PG.txt` / текст из вложений).

Скрипт начинается с **проверочных SELECT**, затем идут UPDATE адресов:

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/razvorachivanie-bekapa/06-sql-script-settings.jpg)

Что меняют (по скрипту на экране):
- `Settings.ApplicationPath`
- `Settings.ApplicationIPPath`
- `Settings.WSSettings` (веб-сервис)
- `Settings.ApplicationInvitePath`
- `Settings.InternalApplicationPath`
- `Settings.WAFileInfoServer`
- `Settings.ApplicationId` — **уникальный** 8-символьный ID для каждого контура
- отключение почты / mail jobs / push tokens / Exchange sync и т.п.

В Query Tool на целевой БД:

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/razvorachivanie-bekapa/07-sql-script-query-tool.jpg)

Подключение Dev БД на записи:

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/razvorachivanie-bekapa/08-pgadmin-dev-host.jpg)

- Host: `192.168.216.119`
- Port: `5432`
- DB: `d10task`

**Важно (со записи):** значения вроде `http://10.222.3.20/` в примере скрипта — **шаблон**. Перед запуском подставьте адреса **своего** контура (web / DB / support), пароли и уникальный `ApplicationId`. Иначе после restore останутся **боевые** URL.

Проверочные SELECT в начале скрипта после выполнения можно не оставлять в финальном прогоне — на записи их использовали, чтобы увидеть текущие настройки.

### Шаг 3. Не забыть post-restore на web-сервере

После restore БД одного SQL недостаточно. На той же встрече отдельно разобраны:
1. останов контейнеров web (`docker compose down`);
2. правка `.env` (`CORE_DB_SERVER` и связанные адреса);
3. подъём контейнеров (`docker compose up -d`);
4. проверка **Провайдеры файлов** в админке.

Подробный чек-лист этих шагов — в инструкции  
https://github.com/hommtoe121-del/test-rep/wiki/Выравнивание-серверов-1Формы

## 4. Риски

| Риск | Почему |
|---|---|
| Забыли поменять адреса в SQL / `.env` | Контур начнёт ходить в **боевую** БД/URL (на записи: был кейс с неотредактированным `.env`) |
| Restore без остановки web | Грязные записи / гонки с приложением |
| Один `ApplicationId` на несколько контуров | Ломается мобильное приложение / идентификация инстанса |
| Не отключили почту / Exchange / push | Тестовый контур шлёт боевые письма и синки |

## 5. Чек-лист поддержки

- [ ] Есть свежий бэкап боя (`192.168.216.187`, каталог `/backup`) или согласован restore с IT
- [ ] Целевой DB-хост известен (пример Dev: `192.168.216.119`)
- [ ] Restore БД выполнен
- [ ] SQL-скрипт из #2070670 заполнен адресами **целевого** контура и уникальным `ApplicationId`
- [ ] Проверочные SELECT показали ожидаемые значения
- [ ] Выполнены шаги выравнивания web (docker / `.env` / file providers) — см. соседнюю инструкцию
- [ ] Проверена админка целевого web: в шапке указана нужная БД
