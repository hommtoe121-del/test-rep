## 1. Что значит «выровнять серваки»

На записи выравнивание = взять свежий бэкап боя и привести **целевые** web+DB к согласованному состоянию:

1. БД восстановлена из бэкапа боя (см. https://github.com/hommtoe121-del/test-rep/wiki/Разворачивание-бэкапа-1Формы).
2. В БД переписаны URL/настройки под целевой контур (SQL-скрипт).
3. На web остановлены контейнеры → поправлен `.env` → контейнеры подняты.
4. В админке проверены провайдеры файлов и факт, что инстанс смотрит в **свою** БД.

Без пунктов 2–4 Dev/Test продолжит работать как «клон боя» и может писать в боевые адреса.

## 2. Порядок работ (чек-лист)

### 2.1. Остановить контейнеры на web **до** правок в БД / `.env`

На записи: PuTTY → `192.168.216.118` → `sudo -i` → `cd /opt/1forma` → `docker compose down`.

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/vyravnivanie-serverov/09-putty-web-dev.jpg)

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/vyravnivanie-serverov/09b-ssh-opt-1forma.jpg)

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/vyravnivanie-serverov/10-docker-compose-down.jpg)

**Устно:** для каждого web-сервера контура — отдельно. Логин SSH тот же, что используют для доступа «как к ВКС» / УЗ 1Формы (на записи: `goryunkov1forma`).

Команды (как на записи):

```bash
sudo -i
cd /opt/1forma
docker compose down
# ... правки БД и .env ...
docker compose up -d
```

### 2.2. Прогнать SQL-скрипт выравнивания в целевой БД

Скрипт из задачи #2070670 (SELECT для проверки + UPDATE адресов, отключение почты/Exchange и т.д.):

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/vyravnivanie-serverov/06-sql-script-settings.jpg)

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/vyravnivanie-serverov/07-sql-script-query-tool.jpg)

Целевая Dev БД на записи:

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/vyravnivanie-serverov/08-pgadmin-dev-host.jpg)

- Host `192.168.216.119`, port `5432`, DB `d10task`

Подставьте в скрипт **свои** ApplicationPath / WSSettings / пароли / уникальный `ApplicationId`. Шаблонные `10.222.3.20` со скрина — не копировать как есть.

### 2.3. Поправить `.env` на web

Файл: `/opt/1forma/.env` (редактор на записи — `nano .env`).

Критично выставить адрес **целевой** БД, например:

- `CORE_DB_SERVER=<IP целевой БД>` (на Dev-записи: `192.168.216.119`)
- согласованные `CORE_DB_NAME` / user (без публикации паролей)

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/vyravnivanie-serverov/12b-nano-env-clear.jpg)

Сохранение в nano (как проговаривали): записать изменения, затем выйти (`Ctrl+O` / `Ctrl+X` — уточняйте по версии nano; на записи искали «редактирование файлов Linux nano»).

**Риск со записи:** если после restore боя на Dev **не** поменять `CORE_DB_SERVER`, приложение будет менять настройки на **боевой** БД.

### 2.4. Поднять контейнеры

```bash
docker compose up -d
```

Дождаться подъёма web.

### 2.5. Проверить админку и провайдеры файлов

Админка Dev на записи показывает связку web↔DB:

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/vyravnivanie-serverov/17-admin-home-db-info.jpg)

Пример с экрана:
- Web: `192.168.216.118` (`1f-core`)
- DB: `192.168.216.119\d10task`

Провайдеры файлов: https://192.168.216.118/spa/administration/file-provider

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/vyravnivanie-serverov/14-admin-file-providers.jpg)

Откройте провайдеры (`MainProvider`, `TaskFilesDB`, при необходимости `TaskFilesDB_backup`) и убедитесь, что Host/строка подключения указывают на **целевую** БД, не на бой.

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/vyravnivanie-serverov/15-file-provider-taskfilesdb.jpg)

![](https://raw.githubusercontent.com/wiki/hommtoe121-del/test-rep/media/vyravnivanie-serverov/16-file-provider-backup.jpg)

На записи: после правок — «Проверить соединение» и «Сохранить»; при необходимости то же для второго файлового провайдера.

## 3. Кто что делает

| Работа | Кто (по записи) |
|---|---|
| Доступы к серверам / Linux / VPN | IT, ориентир — **Пётр** |
| Физический restore бэкапа БД | IT |
| SQL-скрипт + `.env` + file providers | команда 1Формы / админы контура (разбор вёл Дмитрий Перевалов) |
| pgAdmin | нужен доступ; на записи рекомендовали поставить клиент для работы с БД |

**Устно в конце встречи:** до выхода Петра полное выравнивание серверов может быть заблокировано по доступам — планировать заранее.

## 4. Чек-лист поддержки

- [ ] Бэкап развёрнут на целевую БД
- [ ] Web-контейнеры остановлены (`docker compose down`)
- [ ] SQL-скрипт выполнен с адресами целевого контура + уникальный `ApplicationId`
- [ ] В `/opt/1forma/.env` `CORE_DB_SERVER` (и связанные поля) указывают на целевую БД
- [ ] Контейнеры подняты (`docker compose up -d`)
- [ ] В админке в шапке видна правильная пара Web/DB
- [ ] Провайдеры файлов проверены (соединение OK), пароли не светятся в тикетах/вики
