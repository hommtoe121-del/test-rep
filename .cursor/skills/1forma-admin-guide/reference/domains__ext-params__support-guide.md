# Дополнительные параметры — Решение проблем

Источник: https://help.1forma.ru/domains/ext-params/support-guide/

Документ описывает типовые проблемы дополнительных параметров от самых частых к менее частым. Внутри собраны разделы по ДП Таблица, lookup, блокам ДП, правам и видимости, сквозным ДП, настройке и переносу, расчётам, специфическим типам ДП, мобильному приложению, списку задач, смарт-выражениям, локализации, копированию и API. Для каждой проблемы указаны симптом, что проверить, решение и когда обращаться в поддержку 1Ф.
 Как пользоваться этим документом
 Документ организован по типам проблем — от самых частых к менее частым. Для каждой проблемы:

- Симптом — что наблюдает пользователь

- Что проверить — шаги диагностики без доступа к БД

- Решение — что проверить или исправить

- Когда обращаться в поддержку 1Ф — что приложить к обращению

Самая частая тема обращений по ДП. Типичные жалобы: не работает фильтрация, множественный выбор, значения по умолчанию, автосохранение, отображение.

Симптом: пользователь пытается фильтровать строки в табличном ДП, фильтр не реагирует или показывает все строки.
 Что проверить:

- Версия системы — фильтрация в ДП Таблица поддерживается начиная с определённых версий (уточнить у пользователя версию)

- Тип колонки — не все типы колонок поддерживают фильтрацию (lookup-колонки могут не фильтроваться)

- Настройка категории — включена ли фильтрация для этого ДП Таблица в настройках категории
  Решение:

- Убедиться, что версия актуальная

- Проверить, что фильтрация включена в настройках ДП Таблица

- Если проблема с конкретным типом колонки — зафиксировать какой именно тип и версию
  Когда обращаться в поддержку: если фильтрация включена, версия актуальная, но не работает — обращение в поддержку 1Ф с указанием: ID категории, ID ДП, тип проблемной колонки, версия.

Симптом: при использовании множественного выбора строк — не все позиции добавляются, появляются пустые строки, кнопка «Применить» не работает.
 Известное ограничение: кнопка «Множественный выбор» не отображается в НТФ (форма постановки задачи). Это ожидаемое поведение — не требует обращения в поддержку. Множественный выбор доступен только после создания задачи, в МТФ.
 Что проверить:

- Количество выбираемых элементов — есть ли ограничение в настройках

- Воспроизводится ли при выборе небольшого количества (2-3 элемента)

- Есть ли обязательные поля в строке таблицы
  Решение:

- Попросить пользователя попробовать с меньшим количеством элементов

- Проверить, не блокирует ли обязательное поле сохранение

- Если проблема стабильно воспроизводится — фиксировать шаги
  Когда обращаться в поддержку: с описанием шагов воспроизведения, ID категории, ID ДП.

Симптом: значение по умолчанию не появляется при создании задачи (НТФ), удаляется после сохранения строки, рассчитывается некорректно.
 Что проверить:

- Настроено ли значение по умолчанию в настройках колонки ДП Таблица

- Тип значения по умолчанию — статическое или через смарт-выражение

- Если смарт-выражение — корректно ли оно (нет ли ошибки в логике)
  Решение:

- Проверить настройку значения по умолчанию в админке

- Если смарт — попросить пользователя показать текст смарт-выражения

- Для НТФ: проверить, не стоит ли флаг «Не копировать значение из родительской задачи»
  Когда обращаться в поддержку: если настройка корректна, но значение не появляется.

Симптом: после отработки автоматизации/действия значения в таблице не обновляются, при включённом автосохранении очищаются значения.
 Что проверить:

- Включено ли автосохранение строк в настройках ДП Таблица

- Происходит ли проблема после конкретного действия/перехода или при ручном редактировании

- Версия системы
  Решение:

- Попросить пользователя обновить страницу (F5) — если после обновления данные на месте, проблема в отображении

- Если данные пропали и после обновления — обратиться в поддержку 1Ф
  Когда обращаться в поддержку: с указанием: ID задачи где пропали данные, ID ДП, какое действие вызвало проблему.

Симптом: в строке итогов ДП Таблица меняется сумма по колонке типа «Число» или «Деньги» после прокрутки, загрузки следующих строк или обновления таблицы; либо итог не совпадает с ручным подсчётом.
 Ожидаемое поведение: итог рассчитывается отдельным запросом по всем строкам, соответствующим текущим фильтрам (но не более 1000 строк — см. ниже), и не зависит от количества строк, загруженных на экране.
 Что проверить:

- включено ли отображение итога у проблемной числовой колонки;

- меняются ли данные или фильтры таблицы перед изменением итога;

- воспроизводится ли проблема после последовательности: открыть таблицу → зафиксировать итог → прокрутить → обновить таблицу;

- воспроизводится ли проблема одновременно для нескольких числовых колонок;

- количество строк в таблице под текущим фильтром — если больше 1000, заниженный итог ожидаем (известное ограничение, не баг).
  Решение:

- если итог меняется только после изменения фильтра, это ожидаемо: сумма пересчитывается по отфильтрованным строкам;

- если строк под фильтром больше 1000 — заниженный итог соответствует известному ограничению, не требует обращения в поддержку;

- если итог меняется после прокрутки или обновления без изменения данных, фильтров и при количестве строк ≤ 1000 — это несоответствие;

- зафиксировать задачу, ДП Таблица, названия колонок, исходный и изменившийся итог, количество строк и запись экрана.
  Когда обращаться в поддержку 1Ф: если итог меняется без изменения данных/условий фильтрации при количестве строк ≤ 1000.

Симптом: некорректное отображение дат (день/месяц перепутаны), обрезание названий лукапов, нет названия при открытии в отдельной вкладке, проблемы с высотой строк и секциями.
 Что проверить:

- Локаль браузера (для проблем с датами)

- Ширина колонок — достаточна ли для отображения содержимого

- Секции — если включены, проверить нет ли конфликта с другими ДП под таблицей
  Решение:

- Даты: проверить локаль браузера, формат дат в настройках ДП

- Ширина: предложить настроить ширину колонок

- Секции: известная проблема — если под таблицей с секциями нет других ДП, таблица может обрезаться

Симптом: не сохраняется значение в выпадающем списке или лукапе внутри таблицы, иерархический лукап не ищет, @eventparam3 возвращает лишние значения.
 Что проверить:

- Тип колонки (lookup, выпадающий список, иерархический lookup)

- Источник данных лукапа — доступна ли категория-справочник

- Есть ли связанные/зависимые колонки
  Решение:

- Проверить, что категория-справочник доступна и содержит задачи

- Для иерархического лукапа — проверить настройку иерархии в категории-справочнике
  Когда обращаться в поддержку: если источник данных корректен, но выбор не сохраняется.

Симптом: пользователь не может редактировать табличный ДП, хотя по матрице доступа права есть. Гибкие права или проверка по статусам не работает для колонок с множественным выбором.
 Что проверить:

- Права по матрице доступа для ДП в этой категории

- Права по статусам — в каком статусе задача

- Гибкие права — настроены ли EPRights
  Решение:

- Проверить текущий статус задачи и права ДП в этом статусе

- Если матрица доступа показывает права, но пользователь не может редактировать — проверить нет ли конфликта с правами по статусам
  Когда обращаться в поддержку: с указанием: ID пользователя, ID задачи, ID ДП, текущий статус.
 Углублённая SQL-диагностика (при доступе к БД) — в Настройке ДП: Q6 (ExtParamStateView), Q4 (EPRights).

Симптом: при печати карточки задачи содержимое ДП Таблица не отображается, отображается пустым или с нарушенной вёрсткой.
 Что проверить:

- Используется ли стандартный механизм печати (Ctrl+P) или пользовательскый шаблон

- Количество строк и колонок в таблице — большие таблицы могут не влезать

- Браузер пользователя
  Решение:

- Для стандартной печати: это известное ограничение — ДП Таблица может некорректно рендериться в print-режиме

- Рекомендовать использование экспорта (если доступен) вместо печати

- Если критично — обращение в поддержку 1Ф как запрос на доработку
  1.9 Скрытие кнопки добавления строк на НТФ
 Симптом: настройка «Скрыть кнопку добавления строк» не работает на НТФ (форма постановки задачи), хотя на МТФ кнопка скрыта.
 Что проверить:

- Включена ли настройка в параметрах ДП Таблица

- Проверить на МТФ — если там работает, проблема специфична для НТФ
  Решение:

- Известное ограничение: ряд настроек ДП Таблица не применяется на НТФ (аналогично кнопке «Множественный выбор»)

- Обратиться в поддержку 1Ф (как запрос на доработку) с указанием ID ДП и категории
  1.10 Дублирование ДП при совпадении ID пользовательского и системного блока
 Симптом: ДП отображается дважды на форме задачи, если он привязан к пользовательскому блоку ДП, чей ID совпадает с ID системного блока.
 Что проверить:

- Привязан ли ДП к пользовательскому блоку

- Есть ли системный блок с тем же ID (коллизия после переноса или ручного создания)
  Решение:

- Обратиться в поддержку 1Ф — требуется корректировка ID блока в БД

- Предупредить: при ручном создании блоков через SQL возможны коллизии с системными ID

Симптом: при изменении значения в ячейке ДП Таблица с включённым автосохранением таблица на миг показывает лоадер и перечитывается целиком.
 Причина: так происходит, если в таблице есть колонка со смарт-выражением. Сервер не может заранее определить, какие строки затронул пересчёт смарта, и отправляет сигнал полного обновления (`fullRefresh`) — фронт перечитывает грид целиком. Это ожидаемое поведение, а не сбой.
 Что проверить:

- Есть ли в таблице колонки со смарт-выражениями — именно они вызывают полную перечитку

- В таблицах без смарт-колонок изменение ячейки обновляется плавно, без мигания

- На больших таблицах с серверной пагинацией построчного обновления нет, но мигания тоже нет
  Когда обращаться в поддержку: если мигание возникает в таблице без смарт-колонок — с указанием ID задачи и ID ДП.

Вторая по частоте тема обращений. Типичные жалобы: не работает поиск, не подгружаются задачи, иерархия не отображается, фильтрация в таблице лукапа.

Симптом: не отображаются ветки в иерархии, поиск в иерархии не работает, ошибки при открытии иерархического представления.
 Что проверить:

- Настроено ли иерархическое представление в настройках ДП лукап

- Есть ли в категории-справочнике подкатегории (иерархия строится по подкатегориям)

- Достаточно ли прав у пользователя на категорию-справочник
  Решение:

- Проверить настройку «Иерархия» в параметрах лукапа

- Убедиться, что категория-справочник имеет подкатегории с задачами

- Проверить права пользователя на категорию-справочник
  Когда обращаться в поддержку: если настройка корректна, права есть, но иерархия не показывается.

Симптом: при открытии лукапа список задач пуст или неполный, «не подгружаются задачи, если их много».
 Что проверить:

- Количество задач в категории-справочнике (при большом количестве возможны лимиты)

- Настройки фильтрации лукапа — есть ли фильтр по статусам (AllowedStates)

- Права пользователя на задачи в категории-справочнике
  Решение:

- Если задач много (>10000) — это известное ограничение, рекомендовать настроить фильтрацию

- Проверить AllowedStates — возможно, фильтр по статусам отсекает нужные задачи

- Проверить права
  Когда обращаться в поддержку: если задач немного, фильтры корректны, но список пуст.
 2.3 Поиск в лукапе не работает
 Симптом: поиск по тексту/цифрам в лукапе не даёт результатов или ищет некорректно.
 Что проверить:

- Что именно пользователь вводит в поиск (текст задачи? значение ДП?)

- Настройку отображаемых полей лукапа — по каким полям идёт поиск

- Тип лукапа — обычный, выпадающий, табличный с поиском
  Решение:

- Поиск ищет по тексту задачи и отображаемым полям лукапа

- Если поиск по цифрам — убедиться, что поле числовое, а не строковое

- Для табличного: поиск работает по видимым колонкам

Симптом: при выборе всех значений галкой окно закрывается без сохранения, не все поля категории отображаются в настройках параметров в гриде, настройки грида не сохраняются.
 Что проверить:

- Количество выбираемых задач — есть ли ограничение

- Настройки грида в мультилукапе — сохранены ли
  Решение:

- Попробовать выбрать задачи по одной (обход проблемы с массовым выбором)

- Для настроек грида — переоткрыть настройки и сохранить заново
  Когда обращаться в поддержку: если проблема стабильно воспроизводится.
 Отдельный случай (исправлено, влито в dev 08.07.2026): если на MultiLookup-поле настроено смарт-правило на событие «После смены ДП» с условием «был удалён элемент из ДП», удаление одного значения или выбор/снятие всех значений («Выбрать все») приводили к ошибке 500 (внутренняя ошибка сервера). До исправления обходной путь — временно отключить смарт-правило на время массовых операций.
 Отдельный случай (исправлено, влито в dev 05.08.2026): в гриде ДП «Мультилукап» числовые колонки (Число, Деньги, а также число, полученное через связь) не показывали значение, если оно содержало разделитель тысяч (обычно от 1000 — например, «1 234»); значения меньше 1000 отображались нормально. Устранено: числовое значение колонки берётся из типизированного значения исходного ДП, а не из его строкового представления.

Симптом: подчинённый лукап пустой, после выбора значения ведущего ДП зависимый не обновляется.
 Что проверить:

- Настроена ли связь в разделе «Связи параметров» (ExtParamLink)

- Заполнено ли значение ведущего ДП

- Совместимы ли типы ведущего и зависимого ДП
  Решение:

- Проверить наличие связи в админке (Связи параметров)

- Убедиться, что ведущий ДП заполнен и содержит корректное значение

- Попробовать пересохранить значение ведущего ДП
  Когда обращаться в поддержку: если связь настроена, ведущий ДП заполнен, но зависимый пуст.
 Углублённая SQL-диагностика (при доступе к БД) — в Настройке ДП: Q3 (ExtParamLink).

Симптом: после смены типа отображения лукапа (например, «как радио-кнопки») потерялись данные пользователя.
 Что проверить:

- Какой тип отображения был до и после изменения

- Были ли данные в лукапе до смены настройки
  ВАЖНО: Это критичная ситуация. Смена типа отображения может привести к потере данных, если новый тип несовместим со старым форматом хранения.
 Решение:

- Если данные потеряны — немедленно обратиться в поддержку 1Ф — возможно восстановление из резервной копии

- Предупредить пользователя о рисках смены типа отображения у заполненных ДП

Симптом: лукап, настроенный на сводный раздел (несколько категорий), показывает задачи не из всех категорий или работает некорректно.
 Что проверить:

- Настройку источника данных лукапа — указан ли сводный раздел

- Права пользователя на все категории в сводном разделе

- Не пуст ли сводный раздел
  Решение:

- Проверить, что все категории сводного раздела доступны пользователю

- Если часть задач не отображается — проверить фильтры лукапа (AllowedStates может быть несовместим между категориями)
  Когда обращаться в поддержку: если настройка корректна, но лукап показывает неполные данные.

Для проверки настроек лукапа на площадке можно использовать API `/api-core/datasource/`. Этот раздел API обслуживает все типы источников данных, включая лукапы.
 Полезные маршруты:
 Метод Путь Что возвращает `GET` `/api-core/datasource/{id}/config` Схема колонок окна выбора: `taskColumnsSettings[]` с полями `title`, `type`, `isDefault`, `hidden`, `order` `POST` `/api-core/datasource/{id}/data` Строки данных окна выбора (с фильтрами в теле запроса) `{id}` — числовой ID лукапа из AdminSPA (виден в URL: `/administration/data-source-settings/lookup/{id}`).
 Когда использовать:

- Пользователь жалуется, что в окне выбора лукапа не видны колонки → сравнить `/config` с настройками в AdminSPA

- Окно выбора пусто или показывает не те данные → проверить `/data` с пустым фильтром

- Расхождение между тем, что настроено в AdminSPA, и тем, что видит пользователь
  Пример: `curl -s -H "Authorization: Bearer $TOKEN" "https://{host}/api-core/datasource/{id}/config"` → проверить `taskColumnsSettings[].isDefault` и `hidden`.

 Что проверить:

- Версия AdminSPA

- Есть ли ДП в категории (блок нельзя создать в пустой категории)

 Что проверить:

- Настроен ли на блоке ДП или группе блоков ДП этой категории смарт-фильтр видимости или сворачивания (`Скрывать по смарт-фильтру` / `Сворачивать по смарт-фильтру`), ссылающийся на свойство задачи (например, статус)

- До обновления как временный обход: снять привязку смарт-фильтра от видимости блока/группы блоков в этой категории — форма создания откроется, но видимость перестанет учитывать условие на НТФ
  Когда обращаться в поддержку: если версия актуальная (2.268.423+), а форма создания всё равно падает с 500 при наличии смарт-фильтра на блоке/группе блоков — с указанием ID категории, ID смарт-фильтра и текста ошибки/стека.

- Где создана таблица-источник — если через импорт из Excel (попадает в схему `custom`), до v2.268 это воспроизводит ошибку

- Отличие от § 8.7 — здесь причина в разрешении схемы объекта (`custom`/`dbo`), а не в типе данных колонки-значения

- Обновить систему до v2.268 или выше — ошибка полностью устранена

 Что проверить:

- Тип ДП — какие именно ДП не работают

- Если проблема на актуальной версии — обращение в поддержку 1Ф с указанием: платформа, версия МП, тип ДП, шаги воспроизведения

10.1 Изменение ДП в списке задач без обязательного комментария
 Симптом: пользователь может изменить ДП прямо в списке задач, минуя проверку обязательного комментария.

 Симптом: нельзя добавить ДП с типом «Выбор нескольких задач» (Multilookup) в колонки списка задач.
 Решение: не все типы ДП поддерживаются как колонки списка задач. Это ограничение системы.

  13. Копирование значений ДП

Симптом: при копировании задачи или создании подзадачи значения ДП копируются некорректно — лишние ДП копируются, нужные не копируются, или значения искажаются.
 Что проверить:

- Настройку «Копировать значение из родительской задачи» для каждого ДП

- Тип ДП — не все типы корректно копируются (Таблица, Мультилукап — особые случаи)

- Метод создания: через кнопку «Копировать», через смарт, через API
  Решение:

- Проверить настройку копирования в параметрах ДП в категории

- Для смартов: проверить, явно ли заполняются ДП в смарте или ожидается автокопирование

- Если копирование через API — проверить, передаются ли значения ДП в запросе
  13.2 Запрет копирования текста из ДП
 Симптом: пользователь хочет запретить пользователям копировать содержимое ДП (Ctrl+C).
 Решение:

- Штатного механизма запрета копирования текста из ДП нет

- Можно реализовать через пользовательскый JS (SmartScript), но это неполная защита (данные доступны через API)

- Зафиксировать как запрос на доработку
  14. API для работы с ДП

Симптом: пользователь спрашивает, как получить все ДП задачи через API, как обновить ДП типа «Файл» через API, как работать с ДП из Lua-скриптов.
 Что проверить:

- Цель: чтение или запись ДП

- Тип ДП (простые типы, файл, мультилукап, таблица — разные маршруты)
  Решение:

- Чтение всех ДП задачи: `GET /api/task/{taskId}` возвращает ДП в блоке ExtParams

- Обновление простых ДП: `POST /api/extParams/update`

- Обновление ДП Файл: `POST /api/files/upload/ToPreUploadedFiles` → затем привязка к ДП

- Синхронизация с 1С: для лукапов использовать `TCLookupGUIDEPID` — указывать ID ДП-лукапа

- Lua: доступ к ДП через `task.ExtParams[epId]`, запись через `task:SetExtParam(epId, value)`

Что уточнить по любой проблеме с ДП:

- Версия системы — какая версия у пользователя

- ID категории и ID ДП — всегда запрашивать

- Тип ДП — уточнить (Text, Lookup, Table, Through, File, SelectUsers и т.д.)

- Воспроизводимость — стабильно или периодически

- Платформа — web, мобильное, AdminSPA

- Скриншот/видео — попросить при неочевидных проблемах

- Текст ошибки — если есть, включая консоль браузера (F12)
  Когда обращаться в поддержку 1Ф
 Обратитесь в поддержку 1Ф, если столкнулись с одним из следующих:

- Потеря данных (значения ДП исчезли)

- NullReferenceException или серверные ошибки

- Регрессия после обновления (работало, перестало)

- Проблема воспроизводится стабильно, все настройки проверены

- Проблема с производительностью (таймауты)
