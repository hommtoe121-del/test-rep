# Работа с задачами

Источник: https://help.1forma.ru/domains/tasks/business/

Задача — центральная бизнес-сущность платформы 1Форма. Все основные процессы (исполнение, согласование, коммуникации, автоматизация, отчётность) связаны с задачным контуром. В общем случае заказчик ставит задачу конкретному исполнителю, указывает срок и даёт описание сути.
 В системе большая часть объектов — это разного рода задачи. Например:

- Поручение сотруднику подготовить отчёт — задача, поставленная руководителем.

- Входящее обращение, полученное по почте и зарегистрированное в системе — задача, поставленная автоматически (роль автоматического заказчика играет специальный пользователь «Робот 1Ф»).

- Запись в календаре о встрече — задача, поставленная сотрудником самому себе.

- Запись в справочнике компаний-клиентов — тоже задача, только без установленного исполнителя и срока (отсутствие исполнителей и сроков допускается системой).

У задачи есть основные параметры, общие для всех категорий:

- категория и раздел, в которых она живёт;

- статусы и переходы между ними — то, что задача проходит от старта до завершения;

- участники: заказчик, ответственный, исполнители, наблюдатели;

- сроки — плановые и фактические;

- маркеры просрочки и напоминания.
  В каждой категории к этому добавляются дополнения — то, что специфично для конкретного бизнес-процесса:

- дополнительные параметры — поля, нужные именно для этой категории;

- файлы, комментарии, реакции;

- подписи и согласования;

- подзадачи и связи между задачами.

Способы создания:
 Способ Где Кнопка «Создать» в панели навигации Открывает выпадающее меню: Личная задача (категория «Личные задачи» в системном разделе), Встреча, Групповой чат, Выбрать категорию (через дерево категорий) Кнопка создания в панели инструментов категории Из списка задач категории Иконка `+` рядом с категорией в Избранном Только если категория добавлена в Избранное и иконка отображается Краткая форма из ленты Создаёт Личную задачу в системном разделе Для создания новой задачи всегда открывается отдельное окно. Набор полей для заполнения зависит от категории. Некоторые поля могут быть автоматически заполнены значениями по умолчанию — их можно изменить.
 В карточке создания категория меняется кликом по её названию; поиск категории работает по названию, идентификатору категории и номеру задачи внутри неё. Обязательные системные и дополнительные параметры помечены звёздочкой.
 Для создания личной задачи из ленты у категории не должно быть обязательных полей.

Если в настройках категории включена опция «Каждому исполнителю — копию» и в поле «Исполнитель» указано более одного сотрудника, в карточке создания становится активной кнопка «Создать копии» — она создаст отдельную задачу для каждого исполнителя.

Если у категории в дополнительных настройках задан ID шаблонной категории, то по кнопке «Создать задачу», а также по «+» в бизнес-индикаторе, привязанном к этой категории, открывается модалка выбора задач-шаблонов из указанной категории.
 Поведение модалки:

- список шаблонов (грид/лукап) — клик по строке выбирает шаблон;

- кнопка «Создать без шаблона» в футере — обычный сценарий пустого создания;

- кнопка «Отмена» — закрытие без действий.
  Выбор одного шаблона открывает форму создания задачи (НТФ) с данными, предзаполненными из шаблона: текст задачи (название), дополнительные параметры и вложения копируются из шаблона; заказчик подставляется как текущий пользователь; срок валидируется на отсутствие даты в прошлом.
 v2.268+: текст задачи (название) корректно подставляется из шаблона при открытии НТФ. До v2.268 поле названия оставалось пустым.
 Мультивыбор допустим: каждый отмеченный шаблон порождает отдельную задачу-копию в целевой категории.
 Флаг «Пропускать НТФ» в категории меняет поведение: при выбранном шаблоне форма создания не открывается, задача создаётся сразу. В обычной категории происходит переход в МТФ созданной задачи; при создании из бизнес-индикатора перехода в МТФ нет, БИ обновляется на месте.
 Создание из карточки бизнес-инцидента (БИ). При нажатии кнопки «Создать» в карточке бизнес-инцидента (БИ) открывается модальное окно выбора шаблонов задач. Шаблоны отображаются в порядке приоритета, заданном в настройках категории. Создание задачи происходит по правилам краткой формы — заполняются только основные и обязательные дополнительные параметры, без открытия полной формы создания задачи. После создания новая задача не открывается в карточке — пользователь остаётся на странице БИ, при этом дополнительный параметр «Откуда создано» автоматически заполняется ссылкой на исходную задачу БИ.

Карточка задачи состоит из нескольких смысловых блоков:

- Основные (системные) параметры — верхняя часть карточки. Содержат данные, общие для большинства категорий: номер задачи, заказчик, исполнители, дата создания, срок, статус, текст задачи. Заказчик и исполнители отображаются в правой части. Если исполнителей больше трёх — список переносится под текст задачи и отображается в строку. Максимальное количество отображаемых исполнителей — 30; при превышении доступна кнопка «Ещё».


- Дополнительные параметры (ДП) — данные, специфичные для конкретного бизнес-процесса. Набор ДП уникален для каждой категории. Могут быть сгруппированы в блоки и вкладки. Подробнее о типах ДП — ext-params/business.md.
  При закрытии карточки задачи система проверяет, есть ли несохранённые изменения в дополнительных параметрах с клавиатурным вводом. Если фокус находился в таком поле, оно редактировалось, но данные не были сохранены — появляется модальное окно «Несохранённые данные» с предложением сохранить изменения перед уходом. Если изменений не было или все данные уже сохранены, модальное окно не появляется.

-  Файлы — блок отображается, если в задачу вложен хотя бы один файл; поддерживает переключение представлений (Плитка / Таблица / Галерея). Подробнее — files/business.md.


-  Лента — обсуждение задачи между участниками и системные сообщения. Может располагаться справа или снизу (настраивается в профиле пользователя). Подробнее — comments/business.md.


-  Подписи — блок отображается только при наличии запрошенных подписей; после обработки исчезает. Подробнее — signatures/business.md.


-  Подзадачи — блок с деревом подзадач. Отображается при наличии родительской задачи или подзадач.


-  Ресурсы — блок трудозатрат и плановых ресурсов. Отображается если настроен в категории. Подробнее — resources/business.md.


-  Основной маршрут — лента статусов в карточке (если настроен администратором). Позволяет видеть пройденные и предстоящие шаги.


-  Используется — блок задач из других категорий, ссылающихся на текущую через Lookup-поле. Отображается только в категориях, где специально настроен администратором; обычно размещается в нижней части карточки задачи. Подробнее — «Блок „Используется“».

С версии 2.264 администратор может настроить стиль карточек: цвет фона полей, обводку, стиль фона блоков, цвет иконок. Настройки применяются ко всем категориям системы.

В шапке отображаются аватар, путь (категория и раздел), строкой ниже — номер задачи. Справа — кнопки управления. При прокрутке вниз или в режиме «Комментарии» вместо пути выводится текст задачи и текущий статус.

По умолчанию панель инструментов свёрнута. Развернуть её можно кнопкой слева от аватара; повторное нажатие или закрытие задачи сворачивает обратно. Положение не запоминается между открытиями задачи.
 В правой части панели — кнопка закрепления. Активация фиксирует панель в развёрнутом состоянии: она остаётся видимой при прокрутке и взаимодействии с задачей (в т.ч. при открытии задачи во всплывающем окне). Закрепление запоминается и применяется ко всем категориям.
 Состав доступных элементов на панели зависит от прав текущего пользователя и настроек категории.

Перечень кнопок и соответствующих им действий зависит от прав пользователя и настроек категории.

По умолчанию используется системный аватар. По клику на аватар → «Изменить аватар»: можно загрузить своё изображение или выбрать из палитры цвет и иконку.
 Доступные цвета: «Не указано» (≈ серый), «Бренд цвет» (≈ синий), Красный, Жёлтый, Оранжевый, Зелёный, Бирюзовый, Синий, Фиолетовый, Розовый, Коричневый, Серый. Иконку можно выбрать из стандартного набора или загрузить своё изображение.
 Цвет, выбранный для аватара, используется не только в карточке, но и автоматически применяется в таблицах задач: когда задача выбрана как значение Lookup-поля, ячейка в таблице окрашивается в цвет аватара. В каждой категории администратор может предустановить дефолтные цвет и иконку.

Наведение на номер показывает иконку копирования. Скопировать можно тремя способами:

- Кликом по иконке копирования.

- Правой кнопкой → «Скопировать» (только номер задачи) или «Поделиться» (полная ссылка вида `https://<host>/spa/tasks/{taskId}`).

- Клик по самому номеру открывает задачу в новой вкладке.
  Номер копируется с символом `#`. Вставить его можно как `#TaskId`, так и просто числом — система распознаёт оба варианта и убирает `#` автоматически. Это работает не только в строке главного поиска, но и в полях выбора задачи (лукапы, ДП «Ссылка на задачу», окно «Добавить связанную»), в ячейках гридов и при вставке списка номеров через запятую или точку с запятой.

Возможность редактирования зависит от прав и настроек категории. В тексте поддерживаются изображения и HTML (если разрешено в настройках категории — иначе курсор всегда устанавливается в конце текста).
 Скопировать текст — правая кнопка → «Скопировать».
 Если для категории настроена локализация текста, при редактировании отображается окно для ввода значений на разных языках. Пользователю показывается значение в его текущей локали.

По умолчанию кнопки переходов и кнопки действий располагаются под текстом задачи. Администратор может переместить их в конец формы — отдельным блоком после всех параметров, перед лентой.
 После нажатия любой кнопки переходов/действий остальные блокируются до завершения операции, чтобы исключить параллельный запуск.
 Кнопка статуса в правой части шапки также управляет переходом по маршруту: показывает доступные переходы, а пользователю с правом «Администратор задач» — пункт «Принудительный переход» со всеми статусами категории. Если переходов нет, кнопка некликабельна. Названия переходов длиннее 15 символов сокращаются многоточием.
 После принудительной смены статуса визуальное отображение у пользователей, не подписанных на задачу, обновляется только после ручной перезагрузки страницы. Сам инициатор смены становится подписчиком автоматически.

Все задачи имеют единый набор системных параметров:
 Параметр Описание Номер задачи Уникальный идентификатор, присваивается автоматически при создании Заказчик Сотрудник, поставивший задачу. Может быть только один. При смене — прежний заменяется новым Исполнители Один или несколько сотрудников. Ограничений на количество нет. Если пользователь не находится в поиске — у него нет прав на данную роль в этой категории.

При расчёте срока (дедлайна) система опирается на точку отсчёта и интервал времени (рабочие дни/часы/минуты). В смарт-выражениях доступны функции `ДобавитьРабочихДней`, `ДобавитьРабочихЧасов`, `ДобавитьРабочихМинут`.
 Ключевые правила:

- Сдвиг точки отсчёта. Если точка отсчёта приходится на нерабочее время (до начала рабочего дня, после окончания, выходной), она сдвигается на начало ближайшего рабочего дня.

- Перерыв. Если срок переходит на другой рабочий день, к началу следующего дня прибавляется время перерыва (`Рабочее время − Рабочих минут в дне`). Если точка отсчёта и срок в один день и интервал меньше продолжительности дня — перерыв не учитывается.

- Интервал ≥ рабочий день. Если интервал больше или равен продолжительности рабочего дня, вместо часов откладываются полные сутки, а остаток прибавляется по правилам выше.
  В расчётах используются: производственный календарь (рабочие/выходные дни), настройки «Рабочее время (с… по…)» и «Рабочих минут в дне» из общих настроек приложения.

Маршрут — последовательность шагов от начала работы с задачей до завершения. Настраивается администратором в категории (см. categories/business.md). Все задачи одной категории имеют одинаковый маршрут.

В меню «Больше» → «Маршрут задачи» открывается схема в виде графа: статусы — блоки, переходы — стрелки с названиями кнопок.
 Просмотр дизайнера маршрута из карточки задачи без возможности редактирования доступен пользователям, не обладающим правами администратора. Пользователи с правами администратора могут вносить изменения в маршрут, добавлять переходы и статусы, а также переходить к настройкам статуса — аналогично работе в режиме администрирования.

- Серый — последующие статусы, недоступные из текущего.

- В некоторых категориях клик по стрелке выполняет переход (только вперёд; назад — только через кнопки).

- В ленте могут быть доступны скрытые переходы — они не отображаются отдельными кнопками, но доступны через выпадающее меню при клике на блок статуса. Администратор использует их для нестандартных или редко используемых маршрутов.

 При наведении на блок текущего статуса всплывает подсказка с датой перехода и длительностью нахождения в статусе.

В работе с задачей участвуют люди с разными ролями — каждая роль определяет права и ответственность.

Каждая роль наделяет пользователя определённым набором прав и зон ответственности в рамках задачи.
 Роль Описание Заказчик Инициатор задачи. Может быть только один. Имеет расширенные права (блокировка срока, управление конфиденциальностью) Исполнитель Выполняет работы. Может быть несколько. Один из них — ответственный Ответственный Исполнитель, отвечающий за результат. По умолчанию — первый в списке Подписчик Наблюдатель, получающий уведомления о ходе задачи Согласующий Утверждает или отклоняет решения через механизм подписей (см. подписи) Роли могут изменяться в ходе выполнения задачи. Права конкретной роли определяются настройками категории.

Если для задачи назначено несколько исполнителей, один из них должен быть назначен ответственным. По умолчанию ответственным назначается первый исполнитель в списке — справа от него отображается метка «(Ответственный)». Чтобы сменить ответственного, нужно навести курсор на нужного пользователя в списке исполнителей и нажать появившуюся кнопку «Ответственный». Смена ответственного в списке текущих исполнителей остаётся доступна даже без права «Редактировать исполнителей».

Добавление — через меню «Исполнители» или клик по полю в карточке. Можно указать отдельных пользователей или группы (если разрешено в категории). Изменение состава группы влечёт изменение подписчиков задачи. Удаление группы из подписчиков не убирает участников, добавленных через неё, — удаляется только сама привязка к группе.
 Поиск участников работает не только по имени и фамилии, но и по основной должности. Если пользователь не находится в поиске — у него нет прав на эту роль в категории.
 Удаление: заказчика удалить нельзя (только заменить); исполнитель/подписчик удаляется через иконку удаления. При удалении заказчик/исполнитель сначала становится подписчиком, и только потом может быть удалён.

 Кнопка «Делегировать» доступна в меню «Исполнители», если выполнены все условия:

- В категории не запрещено исполнение — в основных настройках не выбрано «Запретить назначение исполнителя» в опции «Назначение исполнителя».

- В настройках вида категории активна опция «Отображать кнопку Делегировать».

- В конфигурации тулбара категории отмечен элемент «Делегировать».

- Задача не находится в терминальном статусе («Завершена» или «Отклонена»).

- У пользователя есть право «Редактировать исполнителей» в категории либо его группе выдано спецправо «Разрешить делегировать задачи, назначенные на себя» — в этом случае он может исключить из исполнителей только себя, назначив вместо себя другого пользователя; менять других исполнителей он не сможет.
  Если задача назначена только одному исполнителю, делегирование может быть ограничено отключённой настройкой категории «Разрешить последнему исполнителю снимать с себя исполнение» даже при наличии у пользователя права «Редактировать исполнителей». Чтобы делегировать задачу в категории с отключённой настройкой, пользователю нужно обладать спецправом «Разрешить делегировать задачи, назначенные на себя».

Категория настраивается администратором в одном из режимов: отключено, выборочно или обязательно (см. categories/business.md). При выборочном режиме включить конфиденциальность для отдельной задачи можно из меню «Больше» в карточке. Активный режим обозначается зелёной иконкой замка вместо красной.
 Если у задачи включён режим конфиденциальности, в шапке карточки — в строке системных параметров, рядом с приоритетом — отображается бейдж «Конфиденциально» (светло-жёлтый, с иконкой щита), видимый всем участникам. Если у пользователя есть право выключить конфиденциальность, бейдж кликабелен: по клику открывается меню с одним пунктом «Выключить конфиденциальность» (дублирует пункт меню «Больше»). Строка системных параметров не выводится, если у задачи нет ни приоритета, ни конфиденциальности.
 В задачах с включённым режимом конфиденциальности:

- Добавлять участников может только заказчик.

- Подписчики (кроме заказчика) не могут отправлять комментарии пользователям вне задачи.

- Запрещён запрос динамических подписей у не-подписчиков.

- Статические подписи не блокируются.

- Эскалация просроченных задач не производится.
  При попытке выполнить запрещённое действие пользователь получает сообщение «Нет доступа к задаче. Для получения доступа Вы можете попросить добавить Вас в подписчики задачи следующих людей».
 Доступ к файлам, связанным с несколькими задачами. Смарт-действие «Копировать значение ДП» может скопировать файл из мультифайлового ДП в другую задачу — он остаётся связан с обеими. Доступ проверяется отдельно для задачи, из которой файл открывают: - конфиденциальность и шифрование смотрят только на эту задачу — режим второй задачи не влияет; - групповые права ДП конфиденциальной задачи-приёмника доступа к файлу не дают; - файл недоступен, только если пользователю не видна ни одна из связанных с ним задач.

Шифрование — отдельный механизм, который скрывает текст задачи, сообщения и файлы от всех пользователей кроме подписчиков и обладателей права «Просматривать зашифрованные задачи». Категория настраивается администратором: отключено, выборочно или обязательно. При выборочном режиме шифрование включается из меню «Больше» в карточке.
 У зашифрованной задачи рядом с номером в карточке отображается иконка замка. Текст скрыт и в списке задач, и в карточке: вместо него — заглушка «(Текст задачи недоступен для просмотра)».
 Особенности:

- Зашифрованные сообщения не отображаются при перевоплощении в аккаунт пользователя, который их видит в обычном режиме.

- Шифрование в чатах недоступно — для шифрования чата его нужно открыть как задачу.

- Поиск по тексту зашифрованных задач отключён по умолчанию. Включается отдельной админской настройкой (см. admin.md).

- ДП остаются видимыми; отдельные ДП «Текст» и «Большой текст» тоже можно зашифровать.
  Шифрование необратимо — расшифровать задачу обратно нельзя. Подробнее в разделе Важные предупреждения.

Крупную задачу можно разбить на подзадачи, которые образуют иерархическое дерево. Подзадачи могут принадлежать разным категориям. Вложенность не ограничена.
 Блок «Подзадачи» в карточке — отображается после блока файлов и перед блоком ресурсов. Показывает родительскую задачу и список подзадач. Каждая строка содержит: аватар категории, заголовок, приоритет, счётчик вложенных подзадач, исполнителей (до 3 включая ответственного), срок (оранжевый — завтра, красный — просрочено). На широких экранах (десктоп) в строке также отображается номер задачи (бейдж с `#`); на средних и мобильных экранах он скрыт.
 Блок не отображается, если у задачи нет ни родительской, ни подзадач. Начальное состояние, видимость, отображение завершённых задач настраиваются администратором в категории — в т.ч. через smart-выражения.
 Процент выполнения родительской задачи = отношение закрытых подзадач к общему числу подзадач всех уровней. Округляется до целого.
 Все подзадачи завершены. Если в блоке «Подзадачи» все задачи завершены, а показ завершённых выключен, вместо пустого списка отображается заглушка с текстом «Все подзадачи выполнены.» и ссылкой «Показать завершенные». Клик по ссылке включает показ завершённых подзадач и разворачивает список.

Блок иерархии поддерживает следующие пользовательские действия со строками.

- Клик по строке — открывает задачу в модальном окне

- «+» — быстрое создание подзадачи

- «Развернуть» — расширенный просмотр со списком подзадач и связей

- Меню «⋯» — дополнительные действия

Создать подзадачу можно:

- Кнопкой «Новая подзадача» на панели инструментов — с выбором категории

- Кнопкой «Поставить подзадачи» — массовое создание через промежуточную таблицу

- Кнопкой «Назначить подзадачей» — назначить уже существующую в системе задачу подзадачей текущей

- Кнопкой «Выбрать дочернюю» — сделать одну из уже существующих задач подчинённой текущей задаче
  При создании подзадачи значения совпадающих ДП копируются из родительской задачи.
 Рекомендуемые категории для подзадач: администратор может настроить список — в окне выбора категории такие категории отображаются над общим деревом.

В тулбаре карточки кнопка с индикатором числа подчинённых и связанных задач → пункт «Подзадачи» → открывается окно со всем деревом подзадач. В дереве раскрывается вложенность до той задачи, из которой открыты подзадачи. Текущая задача в дереве подсвечена. В дереве отображаются не только активные задачи, но также завершённые и отклонённые. Опция «Показывать завершённые» переключает видимость завершённых (отображаются более светлым шрифтом). Система запоминает значение опции для категории.
 Окно показывает базовые поля задачи: текст, статус, исполнитель, срок. Значения колонок соответствуют значениям полей самой задачи — пустые поля задачи отображаются пустыми ячейками. Если в категории подзадачи поле «Срок» скрыто и срок не вводится при создании, колонка «Срок» в окне остаётся пустой.

Меню «Подзадачи» в тулбаре → «Поставить подзадачи». Открывается окно с промежуточной таблицей:

- Заполнить поля (текст, срок, исполнитель, категория) → кнопка `+` создаёт строку.

- Каждая строка редактируется (иконка карандаша) и сохраняется/отменяется (зелёная галочка / красный крестик).

- Когда все подзадачи готовы — кнопка «Поставить подзадачи». В окне выводятся номера созданных задач.

Если категория проектная (включён признак «Категория для проектных задач» или «Содержит проектные задачи»), CSV-файл содержит четыре дополнительные колонки помимо стандартных:
 Колонка Описание Дата начала Плановая дата начала работы над задачей Дата окончания Плановая дата завершения работы Процент выполнения Доля выполнения в виде десятичной дроби с запятой в диапазоне 0–1 (например, `0,35` — 35 % выполнения) Уровень Целое число ≥ 1, задаёт уровень вложенности задачи в иерархии Семантика колонки «Уровень»:

- 1 — корневая задача

- 2 — подзадача корневой

- 3 — подзадача второго уровня и так далее
  Родителем для строки уровня N становится последняя обработанная строка уровня N−1. Порядок строк в CSV — часть контракта: иерархия строится последовательно сверху вниз, и родитель должен идти в файле раньше своих потомков. Уровень не может вырасти больше чем на +1 за раз — пропускать промежуточные уровни нельзя.
 Первая строка CSV должна иметь Уровень = 1. Если значение колонки «Уровень» пустое, нечисловое, меньше 1 или скачет больше чем на +1 от предыдущей строки — задача не создаётся, в ответе появляется сообщение об ошибке с номером строки. Остальные валидные строки продолжают обрабатываться.
 Если в форме постановки задано поле «Родительская задача», все корневые строки CSV (Уровень = 1) становятся подзадачами указанной родительской задачи. Если поле пустое — корневые строки создаются как самостоятельные задачи категории.
 Пример CSV с тремя уровнями вложенности:

В дереве отображаются все подзадачи независимо от прав доступа: задачи без права просмотра не скрываются, а остаются в дереве как структурные узлы — это сохраняет иерархию для доступных дочерних подзадач. У такой задачи все колонки, кроме номера, показывают «Нет доступа» курсивом; перейти в неё по клику нельзя.
 Установить связь можно только при наличии прав на привязываемую задачу. Разорвать связь подзадачи с родительской может пользователь, создавший связь (независимо от прав в категории), пользователь с правом «Администратор задач» или член группы администраторов системы — иконка удаления связи в строке подзадачи.

Иерархия — интерфейс просмотра дерева подчинённых задач. Источник данных — хранимая процедура, что позволяет отображать не только задачи, но и любые древовидные объекты (оргструктуру, группы).
 Путь: `<host>/spa/task-hierarchy/{id}` — где `<host>` — адрес вашего стенда 1Формы, `{id}` — идентификатор иерархии, который выдаёт администратор.
 В зависимости от настроек иерархия отображается в свёрнутом или раскрытом виде — начальное состояние настраивается. Ветви можно раскрывать и сворачивать мышью.

Скопировать, перенести и удалить задачу можно из меню «Больше» в карточке или из контекстного меню списка задач. Пункты появляются только если действие возможно и у пользователя достаточно прав.

При копировании открывается окно выбора целевой категории. Пользователь может копировать только в категории, где у него есть право «Создавать задачи».
 В новую задачу переносятся:

- ДП, совпадающие в исходной и целевой категориях и отображаемые на карточке создания;

- исполнители (если разрешено в настройках новой категории);

- опционально — вложения и подписчики.
  Опция «Установить текущего пользователя заказчиком» заменяет заказчика; при выключенной опции сохраняется заказчик исходной задачи.

Перенос требует прав «Исполнять» в исходной категории и «Создавать задачи» в целевой. Дополнительно проверяется право `Создавать задачи` у заказчика переносимой задачи — если его нет, перенос не выполняется и показывается ошибка.
 При переносе:

- статус задачи сбрасывается на начальный по новому маршруту;

- очищается дата начала работы;

- значения ДП, отсутствующих в целевой категории, удаляются;

- при невозможности переноса показывается окно с причиной и предложением создать новую задачу с предзаполненными ДП.
  Перенос задач из категории с новым интерфейсом задач в категорию со старым интерфейсом не поддерживается.

Удаление физическое и необратимое — данные не подлежат восстановлению. Доступно только администраторам системы и пользователям с правом «Администратор задач» в категории.
 Удаление — крайняя мера. Стандартный сценарий завершения задачи — перевод в терминальный статус («Отклонено», «Отменено» и т.п.) либо перенос в архивную категорию. См. также раздел Важные предупреждения.

- Если заказчик является исполнителем — свою работу он не оценивает

- Оценки могут быть открытыми (видят все) или закрытыми (только пользователи со спецправом на просмотр закрытых оценок)
  Комментарии к оценкам отображаются в ленте задачи.

- Спецправо «Разрешить массовую обработку задач» на группе пользователя.

Инструмент оптимизации распределения трудозатрат, вызываемый из блока «Ресурсы» карточки задачи. Показывает занятость сотрудников по дням в цветовой шкале (зелёный — низкая, жёлтый — средняя, красный — высокая). Поддерживает фильтрацию и автоподбор (исключение перегруженных). Позволяет изменять сроки задачи. Требует право на перенос срока в категории.
 Возможности управления:

- Изменение границ отображаемого периода.

- Перемещение сроков задачи прямо в инструменте.

- Фильтрация исполнителей через окно поиска.

- Параметр «Автоподбор» для исключения перегруженных сотрудников.

- Просмотр списка задач по клику на ячейку трудозатрат.
  Ограничения:

- Дата начала не может быть раньше текущей даты.

- Изменение сроков может потребовать подписи заказчика.

- Необходимо право на перенос срока в категории задач.
  Сохранение изменений кнопкой «Сохранить» обновляет блок «Ресурсы» в карточке задачи.

Лента — основной инструмент мониторинга задач пользователя. Состоит из ленты задач и ленты комментариев. Каждая область содержит набор вкладок.

- Голубой — задачи, где пользователь исполнитель

- Зелёный — задачи, где пользователь заказчик

- Серый — личные задачи

- Красный шрифт — просроченные задачи

- Полужирный — задачи в начальном статусе

 Критерии попадания задачи в повестку:
 Критерий Условие Срок Истекает в этот день, пользователь — ответственный исполнитель Просрочка Задача просрочена, пользователь — ответственный Плановые трудозатраты Запланированы на этот день Контрольные точки Назначены на этот день (исполнитель или ответственный) Просроченные задачи отображаются в списке сегодняшнего дня.
 Иконки в повестке:

- Просрочка — с количеством часов просрочки

- Контрольная точка

- Плановые трудозатраты — с объёмом на день

- Срок — с временем наступления

 В настройках повестки можно исключить «Задачи на подписи» — те, по которым ожидается решение и работы пока выполнять нельзя.

При настройке повторений доступна опция «Учитывать производственный календарь». Если она включена, система сверяет рассчитанные даты с производственным календарём (рабочие дни и праздники РФ). Если очередное повторение попадает на нерабочий день, дальнейшее поведение определяется настройкой «При попадании на нерабочий день»:

- Перенести на ближайший рабочий день:

- Если следующий день — рабочий, повторение переносится на него.

- Если следующий рабочий день уже относится к другому календарному месяцу, повторение переносится назад — на последний рабочий день текущего месяца.

- Не переносить (по умолчанию для новых правил) — повторение в нерабочий день просто пропускается (либо включается как есть, если учёт календаря выключен).
  Примеры переноса:

- Сб 12 апреля → Пн 14 апреля (перенос вперёд, через выходной).

- Сб 30 марта → Пт 29 марта (перенос назад, т.к. следующий рабочий день — 1 апреля, уже другой месяц).
  Время начала при переносе сохраняется от исходной даты.
 Дедупликация. Если на одну и ту же дату приходятся и штатное срабатывание правила, и перенос с нерабочего дня, приоритет у штатного срабатывания. Дублирование не возникает.
 Ограничения — когда перенос недоступен:

- Прекратить после N раз — если выбран режим завершения серии по количеству повторений, перенос недоступен; при выборе этого режима настройка автоматически сбрасывается на «Не переносить».

- Рабочий день месяца (режимы «первый / последний / N-й рабочий день месяца») — перенос недоступен; при включении любого из этих режимов настройка автоматически сбрасывается на «Не переносить».

- Материализация повторений отключена в категории — если в категории выключена настройка «Включить материализацию повторений», перенос недоступен для новых правил (настройка не отображается в интерфейсе). Для правил, где перенос уже был настроен ранее, настройка остаётся доступной, и материализация в этом случае включается принудительно.
  В интерфейсе перенесённые даты отображаются в preview-календаре повторения с маркером и всплывающей подсказкой «Перенесено с {исходная дата}».
 Ежемесячно — N-й рабочий день. В режиме «Каждый месяц» доступна опция выбора конкретного номера рабочего дня (например, 17-й или 20-й). Система вычисляет список всех рабочих дней месяца согласно производственному календарю и выбирает день с заданным порядковым номером. Если в месяце количество рабочих дней меньше указанного номера, для повторения выбирается последний рабочий день этого месяца. Смещение в днях для этого режима не применяется.
 Несколько правил в одной задаче. Для одной задачи можно задать до 10 правил повторения и комбинировать их между собой (например, «каждый Пн, Ср, Пт» + «1-е число месяца» + «15-е января»). В UI повторений рядом со списком правил доступна кнопка «+» для добавления ещё одного. Задачи создаются по объединённому расписанию всех правил: если несколько правил указывают одну и ту же дату, задача создаётся один раз. Общие настройки задачи (срок, материализация, копирование файлов) применяются ко всем правилам сразу. Серия завершается, когда исчерпаны все правила.

В UI повторений (карточка задачи → меню «Срок» → «Повторения») доступен чекбокс «Только рабочие дни». При включении система при расчёте последовательности дат автоматически исключает выходные и праздничные дни согласно производственному календарю.
 Применимость: все типы повторений — «Каждый день», «Каждую неделю», «Каждого месяца» (число и день недели), «Каждый год» (число и день недели).
 Логика применяется ко всем типам интервалов:

- Ежедневно (каждый N день): если выпадающий день нерабочий — повторение не создаётся, отсчёт интервала не сбрасывается. Например, при «каждые 2 дня» пропущенный выходной не влияет на последующие даты.

- Ежедневно / каждый рабочий день: повторения идут по пн–пт и дополнительно исключаются праздники; если по календарю сб или вс рабочий день — повторение создаётся.

- Еженедельно (каждую N неделю + выбор дней недели): повторение создаётся только если выбранный день недели является рабочим по производственному календарю.

- Ежемесячно (N числа или относительный день недели): повторение пропускается при выпадании на нерабочий день.

- Ежегодно (число–месяц или относительный день недели–месяц): повторение пропускается при выпадании на нерабочий день.
  Материализация и перенос с нерабочих дней (с 2.268.332). В категории есть настройка «Включить материализацию повторений» (см. admin.md категорий, § 25 «Повторения задач»). Если она включена, система заранее создаёт все задачи серии на период, заданный системной настройкой (по умолчанию 365 дней). Если выключена — задачи создаются классически, по одной в день наступления каждого повторения.
 Из этого есть исключение: если в правиле повторения настроен перенос с нерабочего дня («При попадании на нерабочий день» = «Перенести на ближайший рабочий день»), система автоматически включает материализацию для такого расписания — независимо от настройки категории. Связано это с тем, что механизм переноса работает только в материализованной ветке исполнения. В UI этот случай не сопровождается отдельным предупреждением: правило просто сохраняется и работает в материализованном режиме.

Задачи могут быть связаны друг с другом иерархическими (родительская-подчинённая) и линейными связями. Одна задача может иметь одновременно и иерархические (вертикальные), и линейные (горизонтальные) связи. Иерархические связи создаются через подзадачи и дерево подзадач, линейные — через связывание задач. На панели инструментов задачи в иконке Подзадачи количество иерархических связей отображается сверху, а количество линейных связей — снизу.
 В рамках линейных связей выделяют два уровня:

- Простая связь — произвольная ассоциация между задачами без направления и семантики.

- Проектные связи — типизированные связи с временной семантикой, используемые в проектном планировании (диаграмма Ганта):
  Тип Описание Семантика Начало → Начало (НН) Задача B начинается, когда начинается A Start-to-Start Начало → Конец (НК) Задача B завершается, когда начинается A Start-to-Finish Конец → Начало (КН) Задача B начинается после завершения A Finish-to-Start Конец → Конец (КК) Задача B завершается, когда завершается A Finish-to-Finish При создании связей из проектного плана тип проставляется автоматически. Связь типа «просто связь» при этом не создаётся.

С версии 2.267.385 в МТФ добавлены два блока:

- Связи — список связанных задач, сгруппированный по типам проектных связей (если они есть).

- Подзадачи — список подзадач текущей задачи.
  Оба блока поддерживают фильтр «показывать завершённые» (по умолчанию — скрыты) и обновляются по сигналу (push через SignalR).
 Каждая строка содержит цветной аватар категории, заголовок, приоритет, счётчик подзадач, до 3 исполнителей, срок (оранжевый — завтра, красный — просрочено). Завершённые задачи — серым цветом. На широких экранах (десктоп) в строке также отображается номер задачи (бейдж с `#`); на средних и мобильных экранах он скрыт.
 По умолчанию в блоке отображаются первые 8 задач — кнопка «Показать все» раскрывает остальные. Клик по строке открывает задачу в модальном окне; меню `…` — дополнительные действия.
 Все задачи завершены. Если в блоке все задачи завершены, а показ завершённых выключен, вместо пустого списка отображается заглушка с текстом «Все подзадачи выполнены.» (блок «Подзадачи») или «Все связанные задачи выполнены.» (блок «Связи») и ссылкой «Показать завершенные». Клик по ссылке включает показ завершённых задач и разворачивает список.
 Сортировка и меню действий. В блоке «Подзадачи» доступно меню сортировки: «По дате создания» (по умолчанию, от более старых к новым), «По приоритету» (от высокого к низкому, задачи без приоритета в конце), «По статусу» (по алфавиту названия статуса), «По исполнителям» (по алфавиту имён, без исполнителя в конце), «По порядку» (по системному порядку). Для блока «Связи» сортировка недоступна.
 Меню «…» каждого блока содержит переключатель «Показывать завершённые» и пункт «Раскрыть в табличном виде». В блоке «Подзадачи» меню дополнительно содержит пункт «Изменить родительскую» (если у задачи уже есть родительская) либо «Назначить подзадачей» (если родительской нет).
 Табличный вид связей: направленные связи. При раскрытии блока «Связи» в табличный вид (меню «…» → «Раскрыть в табличном виде») доступны две колонки направленных проектных связей — «Предшествующие» и «Последующие» (как в диаграмме Ганта). В ячейках — номера связанных задач ссылками; клик открывает задачу в модальном окне, а задача, из карточки которой открыт список, выделена жирным. Рядом с номером показывается тип связи, кроме самой частой «Конец-Начало» (не подписывается): КК — Конец-Конец, НН — Начало-Начало, НК — Начало-Конец.

Через подменю «Подзадачи» в тулбаре или через окно «Подчинённые и связанные» (низ окна — таблица связанных). В окне связанных задач текущая задача в списке выделена цветом.
 Кнопка Действие Создать Открывает выбор категории и карточку создания. В открывшемся окне можно выбрать текущую категорию (отображается отдельным пунктом) либо другую категорию из дерева. В новую задачу копируется текст исходной и значения совпадающих ДП. Опция «Вложения» создаёт независимые копии файлов (без синхронизации с исходной задачей). Поддерживаются рекомендуемые категории Связать Открывает поиск задачи по номеру; `Enter` подтверждает выбор Для связанных задач администратор может настроить рекомендуемый список категорий — они отображаются над общим деревом категорий в окне выбора.
 Быстрый способ связать две задачи: в первой задаче отправить сообщение с символами `+#` и номером второй (например, `+#123456`).

Окно открывается кнопкой «+» в блоке «Связи» или кнопкой «Связать» в тулбаре карточки. В нём задаются связанная задача, тип связи и направление.

- Выбор задачи. Поле работает как поиск: при вводе номера или названия показывается выпадающий список найденных задач (номер + название). Под полем — кнопка «Создать связанную», открывающая выбор категории для создания новой задачи.

- Тип связи (выпадающий список):

- Обычная — без направления;

- Окончание-Начало — одна задача начинается, когда другая заканчивается;

- Начало-Начало — начинаются вместе;

- Окончание-Окончание — заканчиваются вместе;

Линейную связь между задачами может разорвать:

- пользователь, создавший связь (независимо от прав доступа в категории);

- любой пользователь, имеющий доступ к задаче (право просмотра карточки) — в частности, обладатель права «Администратор задач» или член группы администраторов системы.
  Правила для линейной связи и для связи подзадачи различаются. Для разрыва связи подзадачи с родительской недостаточно доступа к задаче — требуется право «Администратор задач» (либо быть создателем связи); см. «Подзадачи и иерархия».
 Если у пользователя нет доступа к связанной задаче, в блоке отображается «Нет доступа», а иконка удаления связи скрыта.

Задачи в системе часто ссылаются друг на друга. Блок «Используется» позволяет из карточки одной задачи просматривать задачи, которые на неё ссылаются. Например, из карточки контрагента — все связанные с ним встречи, договоры и платежи; из карточки мероприятия — списки зарегистрировавшихся компаний; из карточки вакансии — анкеты кандидатов.
 Связь устанавливается через поле ссылки на задачу (Lookup-поле): если в анкете кандидата в поле «Вакансия» выбрана ссылка на задачу-вакансию, эта анкета отобразится в соответствующей вкладке блока вакансии.
 Блок состоит из одной или нескольких вкладок; если вкладок несколько, на отдельных вкладках чаще всего собраны задачи из разных категорий. Блок обычно размещается в нижней части карточки задачи. Записи на вкладках — ссылки на задачи, по клику на запись открывается карточка соответствующей задачи.

Прямо из блока можно создать задачу в той категории, на которую блок ссылается, — кнопкой «Создать» открывается карточка создания задачи. Кнопка видна только пользователям с правом на создание задач в категории. Помимо полной формы доступна краткая форма — при создании заполняются только текст, исполнитель, срок и обязательные поля (при их наличии); в выпадающем меню при этом доступен пункт «Полная форма». Включение быстрой постановки настраивает администратор.

В списке задач блока доступны два режима взаимодействия — просмотр и редактирование. Режим редактирования включается кнопкой на панели инструментов блока. Работа в этих режимах соответствует работе с задачами в табличном представлении списка задач категории.

Для определённых таблиц блока администратор может настроить кнопки, выполняющие определённые действия. Одна кнопка может быть связана с несколькими таблицами, а для одной таблицы — настроено несколько кнопок. Действия могут быть свёрнуты в список, раскрывающийся по кнопке «Действия».

Вид отображения доступен начиная с версии 2.265 «Цефей».
 Помимо стандартного табличного представления задачи в блоке могут отображаться в виде последовательности карточек без панели инструментов и ленты комментариев. Если в блок добавлена только одна таблица, каждая задача помещается в отдельный раскрывающийся блок, заголовком которого служит имя блока «Используется» с порядковой нумерацией (1, 2, 3 и т. д.). Если настроено несколько таблиц, карточки отображаются единой лентой с горизонтальными разделителями. Режим позволяет напрямую из блока просматривать и редактировать параметры, ресурсы и вложения, как в полноценной форме задачи.
