# Гриды — Администрирование

Источник: https://help.1forma.ru/domains/grids/admin/

Администрирование табличного представления задач в 1Форме: индикаторы (тикеры), избранное групп, общие параметры табличного вида и пользовательские настройки колонок и фильтров. Документ описывает формы автоадминистрирования, отдельные SPA-страницы, API администрирования, ключевые настройки и типичные ошибки конфигурации.

Домен grids охватывает настройку табличного представления задач: индикаторы (тикеры), избранное группы, общие параметры табличного вида и пользовательские настройки колонок и фильтров. Администрирование использует три механизма:

- Автоадминистрирование — 1 форма (настройки табличного вида)

- Отдельные SPA-страницы — 2 формы (тикеры, избранное), зарегистрированы в дереве автоадминки, но открывают собственные SPA-страницы

- API администрирования — 1 группа маршрутов (управление группами/папками избранного)

Три механизма управления настройками табличного представления: форма автоадминистрирования, отдельные SPA-страницы и API администрирования.

Где настраивается: SPA-страница `/administration/tickers` (пункт `tickers` в дереве автоадминки) Таблица БД: `dbo.MenuItemTicker`
 11 полей, определяющих цветовые/числовые индикаторы в навигационном меню:
 Группа полей Что контролирует Имя, описание Идентификация тикера Тип индикатора Числовой / цветовой Источник данных SQL-запрос или предопределённый источник Цвет, иконка Визуальное оформление в меню Привязка к пункту К какому разделу меню привязан тикер Как применяется: тикеры обновляются периодически в реальном времени.
 Тип индикатора резолвится по коду, а не по числовому Id. Связь индикатора с его типом (таблица `MenuItemTypes`) определяется по стабильному строковому коду (`MenuItemTypeCodes.Ticker`), а не по числовому `Id`: `Id` в `MenuItemTypes` — автоинкрементный (Identity) и различается между площадками. Поэтому при переносе и диагностике нельзя опираться на конкретное число `Id` типа. Ранее резолв шёл по `Id`, и на площадках, где запись `Ticker` имела `Id ≠ 3`, создание индикатора падало с ошибкой типа.

Где настраивается: SPA-страница `/administration/favorites-groups` (пункт `favourites` в дереве автоадминки) или API администрирования Таблица БД: `dbo.UserLinks`
 18 полей: структура ссылок и папок блока «Избранное группы». Администратор настраивает набор ссылок для группы, которые отображаются у всех пользователей группы.
 Группа полей Что контролирует Группа, папка Привязка к группе и иерархия URL, название Содержание ссылки Тип ссылки Задача / категория / пространство / внешняя Порядок Сортировка в блоке избранного Тип ссылки «Смарт отбор». Требует последовательного выбора: сначала категория, затем конкретный отбор (сохранённое смарт-выражение датасурса) внутри неё. При смене категории выбранный отбор сбрасывается — это ожидаемое поведение, нужно выбрать отбор заново. Если у категории нет сохранённых смарт-выражений (или категория не выбрана), список отборов пуст. При повторном открытии ссылки на редактирование ранее сохранённые категория и отбор подставляются автоматически.
 Тип ссылки «Раздел»: вариант «Все разделы». Помимо выбора конкретного раздела, в списке доступен вариант «Все разделы». При его выборе поле «Представление» блокируется и очищается — представление для такой ссылки не задаётся, а сама ссылка сохраняется как указывающая на все разделы, без привязки к конкретному. При повторном открытии формы вариант «Все разделы» восстанавливается. В блоке избранного пользователя такой элемент раскрывается в полный каталог доступных ему разделов (см. Интерфейс пользователя).
 Редактирование структуры
 В редакторе блока «Избранное группы» поддерживается перетаскивание для перестроения дерева элементов. Администратор может:

- перемещать ссылку в другую папку;

- перемещать папку внутрь другой папки;

- менять порядок ссылок и папок на одном уровне.
  После перетаскивания элемент должен сразу отображаться в новом месте в дереве, до сохранения страницы. Это позволяет сразу проверить, что ссылка или папка попала в нужный раздел и заняла корректную позицию.
 При изменении структуры важно различать два сценария: перенос элемента в папку и перестановка элементов на одном уровне. Если требуется вложить ссылку или папку внутрь другой папки, нужно перетащить элемент именно в узел папки. Если требуется только изменить порядок, элемент нужно переместить между соседними элементами одного уровня.
 Как применяется: блок «Избранное группы» формируется в навигационной панели.

Три категории настроек табличного представления: устаревшие глобальные параметры, пользовательские настройки колонок и сохранённые фильтры.
 Общие настройки табличного вида (UserTaskOnlySettings). Автоадминка → форма `user-task-only-settings`. Таблица БД: `dbo.UserTaskOnlySettings`. 6 полей: глобальные параметры табличного представления задач. Примечание: форма находится в папке «Устаревшее», основные настройки табличного вида теперь задаются через пользовательские колонки и фильтры.
 Пользовательские настройки колонок. API: `/api-core/datasource/{type}/columns/save|reset`. Таблицы БД: `dbo.DataSources`, `dbo.DataSourceColumns`. Пользователь сохраняет видимость, порядок и ширину колонок (отдельно для каждого пользователя). Настройки сбрасываются через `columns/reset`.

 Сохранённые фильтры. API: `/api-core/datasource/{type}/filters`. Таблица БД: `dbo.DataSourceFilters`. Сохранённые фильтры и сценарии выбора. Фильтрация задач и фильтрация табличных ДП обрабатываются раздельно.

Как настраивать произвольный источник — колонки (названия, типы, фильтры), кнопки действий и тулбара, выгрузка в Excel — в отдельной статье Произвольные источники данных. Ниже — только где хранится настройка.
 Таблица БД: `dbo.DataSourceSettings` (ключи вида `sptable_<имя>`)
 Произвольный источник данных — это грид поверх объекта БД. Источник настраивается парой «тип + имя объекта»; тип определяет, какой ключ JSON-настройки будет заполнен:
 Тип источника Ключ настройки Объект на MS SQL Объект на PostgreSQL Таблица `tableName` таблица таблица Представление `viewName` представление представление Функция `funcName` функция `(userId[, taskId])` функция `(userId[, taskId])` Хранимая процедура `spName` хранимая процедура одноимённая PG-функция Хранимая процедура без ResultSet `spName` + флаг процедура без выборки не применимо Особенности:

- Ключи взаимоисключающие: при сохранении источника заполняется ровно один ключ, остальные обнуляются. Хранить одновременно `spName` и `funcName` в одной настройке нельзя.

- На PostgreSQL-стендах источник типа «Хранимая процедура» работает через одноимённую функцию: имя процедуры приводится к виду `dbo.<имя в нижнем регистре>` (из `[dbo].[RoadMapInSubcat]` получается `dbo.roadmapinsubcat`). Настройку источника менять не нужно — требуется, чтобы на стенде существовала PG-функция с этим именем и параметрами `(p_userid int default null, p_taskid int default null)`.

- Если PG-функции с таким именем нет, запрос данных возвращает HTTP 400 «The requested data source is not available.» — это ожидаемая диагностика, а не сбой сервера.

Где настраивается: API администрирования (`/api/admin/extparams/table/{tableId}/formatting-rules`) Таблица БД: `dbo.ExtParamTableColumnFormattingRules` (FK → `ExtParamTableSettings.Id`)
 Условное форматирование позволяет задать правила подсветки ячеек в табличных ДП по значению — аналогично условному форматированию в Excel. Правила настраиваются отдельно для каждой колонки через API администрирования.
 Маршруты API:
 Метод Маршрут Назначение GET `/api/admin/extparams/table/{tableId}/formatting-rules` Все правила для ДП Таблица (включая неактивные) POST `/api/admin/extparams/table/{tableId}/formatting-rules` Создание правила PUT `/api/admin/extparams/table/{tableId}/formatting-rules/{ruleId}` Обновление правила DELETE `/api/admin/extparams/table/{tableId}/formatting-rules/{ruleId}` Удаление правила `tableId` — ID самого ДП Таблица; `ColumnId` передаётся в теле запроса.
 Модель правила:
 Поле Тип Описание ColumnId int (FK → ExtParamTableSettings.Id) На какую колонку правило RuleType enum `EpTableFormattingRuleType` Тип правила: числовые (GreaterThan, Between, Min/Max, …), текстовые (Contains, StartsWith, …), Duplicates ValueX string (nullable) Первое значение условия; не используется для Min/Max/Duplicates ValueY string (nullable) Второе значение условия; используется только для Between/Outside Color enum `EpTableFormattingColor` Цвет (Red, Green, Yellow, …) — 12 значений палитры ColorTone enum `EpTableFormattingTone` Тон (None, White, Light, Normal, Dark) Priority int Приоритет: правило с меньшим Priority применяется первым IsActive bit Активность правила Правила форматирования интегрированы в настройки колонок табличного ДП. При загрузке настроек колонки правила включаются в ответ автоматически.
 Полный справочник типов правил (числовые/текстовые/универсальные), палитры цветов и тонов, логики валидации — в справочнике настроек ДП Таблица (раздел «Условное форматирование колонок»).
 Очистка HTML в ячейках. Содержимое ячеек с HTML-разметкой (HTML-колонки, значения с разметкой) очищается перед показом: скрипты, небезопасные теги и inline-стили (атрибут `style`) из разметки ячейки удаляются. Для окрашивания и оформления ячеек по значению используйте условное форматирование (выше), а не inline-стили в содержимом ячейки.

Каждый объект массива:
 Поле Тип / Default Назначение `subcats` `int[]` ID категорий, для которых включается новый грид. Игнорируется при `allSubcats=true` `users` `int[]` ID пользователей, к которым применяется правило `allUsers` bool / `false` Применить ко всем пользователям `allSubcats` bool / `false` Новый грид для всех категорий `myTasks` bool / `false` Включить в разделе «Мои задачи» `tickers` bool / `false` Включить для тикеров (индикаторов) Логика применения: правило срабатывает для пользователя, если `users` содержит его ID или `allUsers=true`. При наличии хотя бы одного подходящего правила с `allSubcats=true` — новый грид включается для всех категорий; иначе — объединяются `subcats` из всех подходящих правил. Флаги `myTasks` / `tickers` ставятся в `true`, если хотя бы одно подходящее правило содержит их `true`.
 Примеры:
 Все пользователи, все категории, включая «Мои задачи» и тикеры: `[{"subcats":[],"users":[],"allUsers":true,"allSubcats":true,"myTasks":true,"tickers":true}]
`
 Конкретные пользователи и категории: `[{"subcats":[5574],"users":[6736],"allUsers":false,"allSubcats":false,"myTasks":false,"tickers":false}]
`
